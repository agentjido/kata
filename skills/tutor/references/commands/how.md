# How

**Result:** A concrete account of how the subject works or how to perform the
requested action.

**Done:** The learner can follow the mechanism or next action without guessing
about a material step.

Start with a plain definition. Explain the smallest useful sequence, mechanism,
or worked example. Tie it to the learner's real task when one is available.
Show source facts when the behavior depends on code, documentation, or current
tool behavior. Separate observed behavior from inference.

When the learning map selects a concept, read only that concept file and use it
as the local teaching source. Add detail only when the learner's request needs
it.

Do not replace an explanation with a list of names. Do not add history or
rationale unless Tutor also selects `why`.
