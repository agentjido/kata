# Check the return

**Practice:** Decide whether a returned result is acceptable, needs repair, or
lacks evidence.

Concepts: [evidence](../concepts/evidence.md) and
[uncertainty](../concepts/uncertainty.md).

1. Identify the exact returned result and agreed completion conditions.
2. Match each material condition to direct evidence.
3. Separate proved facts, worker claims, and unknowns.
4. Ask the learner for an acceptance, repair, or evidence request with reasons.
5. Give feedback on the strongest unsupported part of the decision.

Worked example:

```text
Returned result: A summary that says all eight customer interviews mention
slow exports.
Condition: Each claim has a source interview.
Evidence: Five interview notes mention slow exports. Three do not.
Decision: Repair. Correct the count to five of eight, name the five
interviews, and mark the other three as "no mention".
```

Common mistake:

```text
The summary reads well and the agent said it checked the notes. Accepted.
```

Good writing and a worker claim are not evidence. The decision must name the
condition, the source that was inspected, and what the source showed.

Complete when the learner makes a supported decision or writes a specific
repair request. A worker saying “complete” is not sufficient evidence.
