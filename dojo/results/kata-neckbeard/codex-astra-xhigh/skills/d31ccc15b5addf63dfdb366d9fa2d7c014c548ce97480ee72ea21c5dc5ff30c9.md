# Kata Neckbeard

Explain the current system. Support each material claim with a source reference.
Use the user's question from the current conversation to set the scope.
Do not edit files or change code.

## Inspect the project

1. Identify the target repository. In a workspace with several repositories,
   use the conversation to select the correct one. Ask if the target is unclear.
2. Read its project instructions and README. If `guides/README.md` exists, use
   it to find relevant guides. Otherwise, find the relevant documentation in
   the project. Do not require a `guides/` directory.
3. Read the documents that address the question. Note their stated behavior,
   requirements, configuration, and limits.

## Check the implementation

1. Trace the relevant entry points, functions, data flow, and configuration in
   the current source code. Use tests to check the expected behavior.
2. For each aspect of behavior asked about, compare the relevant documentation
   with code and test source. State explicitly where they disagree and cite
   both sources. Use code as evidence of implemented behavior; preserve
   documented requirements as evidence of intent. Limit further comparison
   reads to missing evidence, contradictions, or dependencies that could change
   the answer. After checking the relevant sources, stop expanding this
   comparison when each requested aspect has supporting lines or an explicit
   evidence gap. Complete the remaining checks below.
3. Do not infer a design reason from code alone. Look for a decision record,
   comment, or relevant history when the question asks why a choice was made.
4. State what static inspection cannot confirm. Do not claim that a test passed
   or that deployed behavior was verified unless you have that evidence.

## Report the answer

- Answer the specific question first. Keep the explanation direct and factual.
- Link to the source files and relevant lines for each material claim. Include
  documentation references when they explain intent or conflict with the code.
- Explain relevant limits, prerequisites, and unresolved questions.
- Separate confirmed facts from deductions. If evidence is missing, say so.
- Use a short list or diagram only when it makes the explanation clearer.
- Before responding, check that the references support the answer and refer to
  the current files in the target repository.

Keep this work limited to investigation and reporting. Do not repair code or
documentation as part of this skill.
