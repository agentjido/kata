# Kata Setup

Collect documentation for later review. Do not rewrite, classify, or claim to verify its content against implementation.

## Inspect and select

- Resolve the requested project root; ask if unclear. Read applicable instructions, root README, existing Docs Kata rules, index, intake log, and `templates/docs-agents.md` beside this skill. Check Git status; preserve local edits.
- Inventory prose and supporting assets in project documentation locations. Search links and build configuration for consumers. Extensions and category folders do not prove documentation status or prior review.
- Preserve root entry points, policies, licenses, changelogs, and all agent instruction files and their scope. Exclude source, tests, fixtures, dependencies, generated or vendored documents, installed skills, and separate repositories. Do not follow symlinks outside the project.
- Include unprocessed category documents on first setup. On repeats, retain inbox contents and processed documents. Retain and report documents whose prior setup state is unclear.
- Retain files needed at fixed paths by builds, websites, published URLs, or package consumers unless this change preserves those uses. Log exceptions and reasons.
- Show the inventory and proposed moves. Setup authorizes routine moves; ask only about unresolved content, behavior, instruction, or path conflicts. Continue independent work.

## Create and collect

1. Create missing `docs/AGENTS.md`, `docs/README.md`, and `docs/inbox/README.md`. Use the template for new instructions; otherwise preserve existing rules and merge one reusable `## Docs Kata` section. Never silently replace conflicting rules.
2. Preserve index content; link to rules, inbox, and existing processed documents. Add a missing documentation index link to the root README. Create category folders only during processing.
3. Preserve intake content. Record original path, actual destination, intake date, status, and exceptions with reasons.
4. Map individual inventoried files into `docs/inbox/`, preserving project-relative source paths. Reserve setup and instruction files. Exclude the inbox; never move a directory into itself or its descendants.
5. Check destinations; never overwrite or discard either file, even when identical. Choose a free suffix for collisions.
6. Hash current files before moving, including local edits; verify destination content before link repairs. Never restore from Git or stage changes automatically.
7. Repair affected relative links in moved and referring files using old and new locations, including assets, fragments, and reference-style links. Preserve external URLs. Limit content changes to path repairs. Preserve required consumers before moving.
8. Log completed moves. After interruption, reconcile sources, destinations, and intake records before continuing. Preserve differing copies.

## Verify and report

Check setup files, inventory, assets, local edits, touched links, and diff. Run an appropriate existing docs check without installing tools. Ensure repeats preserve instructions and processed documents without duplicate moves, sections, records, or links. Report target root, created files, move count, exceptions, unresolved items, and checks. State that inbox contents await review.
