# Kata Setup

Collect documentation for review. Do not rewrite, classify, or claim to verify its content.

## Inspect first

- Resolve the project root. Ask only if it is unclear or a conflict cannot be resolved. Read applicable instructions, Git status, the root README, documentation indexes, intake records, Docs Kata rules, and `templates/docs-agents.md` beside this skill.
- Inventory documents, assets, relative links, and fixed consumers such as builds, sites, URLs, and packages. A directory or file type does not prove review status.
- Preserve local edits. Protect root entry points, policies, licenses, changelogs, and every agent instruction file. Exclude source, tests, fixtures, dependencies, generated or vendored content, installed skills, separate repositories, and symlinks that leave the project.
- On first setup, select unprocessed category documents. On repeats, preserve inbox files and processed documents. Keep unclear items in place. Show proposed moves and fixed-path exceptions before changes.

## Set up and collect

1. Create missing `docs/AGENTS.md`, `docs/README.md`, and `docs/inbox/README.md`. Use the template for new instructions. Preserve existing instructions and merge one reusable `## Docs Kata` section.
2. Preserve index content. Link the documentation index to the rules, inbox, and processed documents. Add its link to the root README only if missing. Create category directories only during processing.
3. Move each selected file under `docs/inbox/`, retaining its project-relative path. Reserve setup and instruction files, exclude the inbox, and never move a directory into itself or its descendant.
4. Check destinations before each move. Never overwrite or discard a copy, including identical content. For a collision, use an unused suffix and record the actual destination.
5. Hash the current source before moving it. Verify destination content before link repair. Never restore from Git or stage changes.
6. Repair only relative links affected by moves, including links to assets, fragments, and reference definitions. Check moved files and their referrers. Do not change external URLs. Keep fixed consumers in place unless a move keeps them valid.
7. Record each completed move with its original project-relative path, actual destination, date, status, and exceptions. On interruption or repeat, reconcile sources, destinations, hashes, and intake records. Preserve different copies. Do not duplicate moves, sections, records, or links.

## Verify and report

Check setup files, inventory, assets, local edits, relative links, fixed consumers, and the diff. Run an existing documentation check without installing tools. Report the root, created files, completed move count, exceptions, unresolved items, and checks. State that inbox content awaits review.
