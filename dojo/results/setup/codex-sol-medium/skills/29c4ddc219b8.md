# Kata Setup

Collect documentation for review. Do not rewrite, classify, or claim to verify its content.

## Inspect first

- Resolve the project root. Ask only if it is unclear or a conflict needs a decision. Read applicable instructions, Git status, the root README, documentation indexes, intake records, Docs Kata rules, and `templates/docs-agents.md` beside this skill.
- Inventory documents, assets, relative links, and fixed consumers such as builds, sites, URLs, and packages. A path or file type does not prove review status.
- Preserve local edits, root entry points, policies, licenses, changelogs, and all agent instruction files. Exclude source, tests, fixtures, dependencies, generated or vendored content, installed skills, separate repositories, and symlinks outside the project.
- Select only clearly unprocessed category documents. On repeats, preserve inbox and processed content. Leave unclear items in place. Show proposed moves and fixed-path exceptions before changes.

## Set up and collect

1. Create missing `docs/AGENTS.md`, `docs/README.md`, and `docs/inbox/README.md`. Use the template for new instructions. Preserve existing instructions and merge one reusable `## Docs Kata` section.
2. Preserve index content. Link the documentation index to the rules, inbox, and processed documents. Add the index link to the root README only when missing. Create category directories only during processing.
3. Move each selected file under `docs/inbox/`, retaining its project-relative path. Reserve setup and instruction files, exclude the inbox, and do not move a directory into itself or a descendant.
4. Before each move, hash the source and check the destination. Never overwrite or discard a copy, including identical content. For a collision, use an unused suffix and record the actual destination. Verify destination content before link repair. Do not restore from Git or stage changes.
5. Repair only relative links affected by moves, including asset, fragment, and reference-definition links. Check moved files and referrers. Leave external URLs unchanged. Keep fixed consumers in place unless their validity is preserved.
6. Record each move with its original project-relative path, actual destination, date, status, and exceptions. After an interruption or on a repeat, reconcile sources, destinations, hashes, and intake records. Preserve different copies. Do not duplicate moves, sections, records, or links.

## Verify and report

Check setup files, inventory, assets, local edits, relative links, fixed consumers, and the diff. Run an existing documentation check without installing tools. Report the root, created files, move count, exceptions, unresolved items, and checks. State that inbox content awaits review.
