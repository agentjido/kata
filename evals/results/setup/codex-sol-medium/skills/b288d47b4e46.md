# Kata Setup

Collect documentation for review. Do not rewrite, classify, or claim to verify its content against implementation.

## Inspect first

- Resolve the project root. Ask if unclear. Read applicable instructions, the root README, Docs Kata rules, the documentation index, the intake log, and `templates/docs-agents.md` beside this skill. Check Git status and preserve local edits.
- Inventory documentation and assets. Search links, build files, site configuration, and package data for consumers. Extensions and category folders do not prove prior review.
- Preserve root entry points, policies, licenses, changelogs, and all agent instruction files. Exclude source, tests, fixtures, dependencies, generated or vendored content, installed skills, and separate repositories. Do not follow a symlink outside the project.
- On first setup, include unprocessed category documents. On repeats, preserve inbox files and processed documents. Retain and report files with unclear prior state.
- Keep files at fixed paths when builds, sites, published URLs, or packages require them, unless their use remains valid. Record exceptions and reasons.
- Show the inventory and proposed moves. Routine moves need no approval. Ask about unresolved instruction, content, path, or behavior conflicts.

## Create and collect

1. Create missing `docs/AGENTS.md`, `docs/README.md`, and `docs/inbox/README.md`. Use the template for new instructions. Preserve existing rules and merge one reusable `## Docs Kata` section. Report conflicts; do not replace their rules.
2. Preserve index content. Link to the rules, inbox, and processed documents. Add a missing documentation-index link to the root README. Create category folders only during processing.
3. Preserve the intake log. For each move, record original path, actual destination, intake date, status, and exceptions.
4. Move each selected file into `docs/inbox/` with its project-relative path. Reserve setup and instruction files. Exclude the inbox. Never move a directory into itself or a descendant.
5. Check each destination. Never overwrite or discard a file, including an identical file. Use an unused suffix for a collision.
6. Hash each current source, including local edits, before moving it. Verify destination content before link repair. Do not restore from Git or stage changes.
7. Repair relative links affected in moved and referring files. Use old and new locations. Include assets, fragments, and reference-style links. Keep external URLs unchanged. Make no other content edits. Preserve fixed consumers before moving.
8. Log completed moves only. After an interruption, reconcile sources, destinations, and intake records. Preserve different copies.

## Verify and report

Check setup files, inventory, assets, local edits, repaired links, and the diff. Run a suitable existing documentation check without installing tools. Repeats must preserve instructions and processed documents without duplicate moves, sections, records, or links. Report the root, created files, move count, exceptions, unresolved items, and checks. State that inbox content awaits review.
