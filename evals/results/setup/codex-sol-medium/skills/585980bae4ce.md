# Kata Setup

Collect documentation for review. Do not rewrite, classify, or claim to verify content.

## Inspect first

- Resolve the project root; ask if unclear. Read applicable instructions, the root README, documentation indexes, intake records, Docs Kata rules, and `templates/docs-agents.md` beside this skill. Check Git status and preserve local edits.
- Inventory documentation and assets. Find links and fixed consumers in builds, sites, URLs, and packages. An extension or category folder does not prove review.
- Preserve root entry points, policies, licenses, changelogs, and every agent instruction file. Exclude source, tests, fixtures, dependencies, generated or vendored content, installed skills, separate repositories, and symlinks that leave the project.
- On first setup, include unprocessed category documents. On repeats, preserve inbox files and processed documents. Keep and report files whose state is unclear.
- Show the inventory, proposed moves, and fixed-path exceptions. Routine moves need no approval. Ask about unresolved instruction, content, path, or behavior conflicts.

## Set up and collect

1. Create missing `docs/AGENTS.md`, `docs/README.md`, and `docs/inbox/README.md`. Use the template for new instructions. Preserve existing instructions and merge one reusable `## Docs Kata` section; do not replace rules.
2. Preserve index content. Link the documentation index to the rules, inbox, and processed documents. Add its link to the root README only if missing. Create category folders only during processing.
3. Preserve the intake log. For each completed move, record the original project-relative path, actual destination, intake date, status, and exceptions.
4. Move each selected file under `docs/inbox/` while retaining its project-relative path. Reserve setup and instruction files, and exclude the inbox. Never move a directory into itself or its descendant.
5. Check every destination. Never overwrite or discard any copy, including an identical copy. If a path collides, select an unused suffix and log the actual destination.
6. Hash each current source, including local edits, before moving. Verify destination content before link repair. Do not restore from Git or stage changes.
7. Repair only relative links affected by moves, in moved files and files that refer to them. Account for old and new locations, assets, fragments, and reference-style links. Keep external URLs unchanged. Keep fixed consumers in place unless their use remains valid after a move.
8. Log only completed moves. After interruption or on a repeat, reconcile sources, destinations, hashes, and intake records. Preserve different copies. Do not duplicate moves, sections, records, or links.

## Verify and report

Check setup files, inventory, assets, local edits, relative links, fixed consumers, and the diff. Run an existing documentation check without installing tools. Report the root, created files, move count, exceptions, unresolved items, and checks. State that inbox content awaits review.
